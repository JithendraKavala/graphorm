# M10 — Nexus Commerce Validation

**Status:** ⚪ Not Started
**Depends on:** M8, M9

---

## Objective

Validate GraphORM against a realistic, complex enterprise application. The Nexus Commerce example must demonstrate that GraphORM eliminates repetitive DAO and resolver boilerplate for real-world workloads while handling complex queries, transactions, and concurrency correctly.

---

## Scope

### Application Domains

#### Organization and Access
- Organizations (multi-tenant)
- Users, roles, permissions
- API keys

#### Product Catalog
- Products, variants, attributes
- Categories (hierarchical tree)
- Pricing (base price, promotions, tier pricing)
- Images and digital assets

#### Warehouses and Inventory
- Warehouses and storage locations
- Inventory levels per SKU per warehouse
- Inventory reservations and locks
- Low-stock notifications

#### Suppliers and Procurement
- Suppliers and contracts
- Purchase orders and line items
- Goods receipt

#### Customers and Orders
- Customers (individuals and B2B accounts)
- Shopping carts
- Orders, order items, order status lifecycle
- Order history and audit trail

#### Payments and Refunds
- Payment methods and processors
- Transactions (authorization, capture, void)
- Refunds and partial refunds

#### Shipments and Returns
- Shipments, tracking numbers, carriers
- Returns, return reasons, return items
- Restocking

#### Promotions and Loyalty
- Discount codes, percentage/fixed discounts
- Loyalty points and tiers
- Campaign rules

#### Analytics and Reporting
- Order volume by period
- Revenue by product, category, region
- Inventory turnover

---

### Integration Scenarios

| Scenario | Tests |
|----------|-------|
| Deep nested GraphQL query | `Order → Items → Product → Category` with 4-level nesting |
| Complex relational filters | Orders with items whose product matches a category, with stock constraints |
| Multi-table joins | Revenue report joining Orders, Items, Products, Promotions |
| Aggregation | Total revenue per product category per month |
| Concurrent purchasing | 100 concurrent threads buying the last unit of a product |
| Inventory reservation | Reserve stock, complete order, release on failure |
| Refund workflow | Full and partial refund, inventory restocking |
| Transaction correctness | Order creation rolls back fully on payment failure |
| Reporting queries | Analytics queries with CTEs and window functions |
| Query-count verification | No N+1 queries in any primary workflow |
| Performance measurement | P50/P95/P99 latency for key operations |

---

## Acceptance Criteria

- [ ] The Nexus Commerce application starts with `mvn spring-boot:run`
- [ ] The GraphQL API for `orders { items { product { category } } }` returns correct data with exactly 4 queries
- [ ] 100 concurrent threads competing for the last unit of a product result in exactly 1 successful purchase and 99 rejections
- [ ] Full order creation fails atomically when payment fails (no order record, no inventory decrement)
- [ ] The revenue-by-category report returns correct totals verified against manually computed expected values
- [ ] All integration test scenarios pass
- [ ] No primary workflow produces N+1 queries
