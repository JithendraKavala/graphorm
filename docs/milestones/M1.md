# M1 — Core Metadata Engine

**Status:** ⚪ Not Started
**Depends on:** M0

---

## Objective

Establish the internal representation of the data model. All other modules — schema parser, query engine, JDBC layer, GraphQL integration — depend on the metadata model defined here. It must be correct, complete, and stable before anything else is built on top of it.

---

## Scope

### Model Metadata
- `EntityMetadata` — table name, fields, primary key, unique constraints, relationships
- `FieldMetadata` — field name, column name, scalar type, nullability, default value, indexed, unique, sensitive flag
- `RelationshipMetadata` — relation name, relation type, referenced model, join column(s), inverse field
- `PrimaryKeyMetadata` — single-column and composite primary keys

### Scalar Types
- `String`, `Int`, `Float`, `Boolean`, `DateTime`, `BigDecimal`, `UUID`, `JSON`
- PostgreSQL-specific: `Jsonb`, `IntArray`, `StringArray`
- Nullable variant of each

### Relationship Types
- `ONE_TO_ONE`
- `ONE_TO_MANY`
- `MANY_TO_ONE`
- `MANY_TO_MANY` (with join table metadata)

### Model Registry
- `ModelRegistry` — registers and looks up `EntityMetadata` by model name or Java class
- Thread-safe; initialized at startup; read-only after initialization

### Metadata Validation
- Duplicate model names rejected
- Duplicate field names within a model rejected
- Relationship references to unknown models rejected
- Circular relationships detected and reported (not necessarily rejected — may be valid for self-referential models)
- Primary key presence enforced

### Core Exception Hierarchy
- `GraphOrmException` (base)
  - `ConfigurationException`
  - `EntityNotFoundException`
  - `DataAccessException`
    - `DuplicateKeyException`
    - `ForeignKeyViolationException`
    - `DataIntegrityViolationException`
  - `SchemaValidationException`
  - `QueryPlanningException`
  - `ReadOnlyViewException`
  - `OptimisticLockException`
  - `AccessDeniedException`

---

## Expected Deliverables

1. `graphorm-core` module contains a complete, immutable metadata model
2. `ModelRegistry` can store and retrieve metadata for any registered model
3. Invalid metadata is rejected with clear, actionable error messages
4. All public APIs are documented with Javadoc
5. Unit test coverage for all metadata classes and validation logic

---

## Acceptance Criteria

- [ ] `EntityMetadata` can represent the following realistic model: Order (id, createdAt, status, customerId) with a many-to-one Customer relationship and a one-to-many OrderItem relationship
- [ ] Invalid metadata is rejected with a `ConfigurationException` or `SchemaValidationException` containing a human-readable message
- [ ] `graphorm-core` does not import any Spring, GraphQL Java, or JDBC classes
- [ ] Unit tests pass: `mvn test -pl graphorm-core`
- [ ] No module has a dependency on `graphorm-core` that creates a circular graph
