# M7 — Spring Boot Starter and CLI

**Status:** ⚪ Not Started
**Depends on:** M6

---

## Objective

Make GraphORM easy to integrate into real Spring Boot applications with minimal configuration. The CLI allows developers to validate schemas and generate Java client code.

---

## Scope

### Spring Boot Auto-Configuration
- `GraphOrmAutoConfiguration` — creates beans for `DataSource` (HikariCP), `JdbcExecutor`, `ModelRegistry`, `GraphOrmClient`, `GraphQLSchema` wiring
- `@EnableGraphOrm` annotation — opt-in activation
- Configuration properties under `graphorm.*`:
  - `graphorm.schema-path` — path to `.graphorm` file
  - `graphorm.graphql.schema-path` — path to `.graphqls` file
  - `graphorm.datasource.*` — connection pool settings
  - `graphorm.graphql.complexity-limit`
  - `graphorm.graphql.depth-limit`

### Schema Discovery
- Schema file resolved from `graphorm.schema-path` on the classpath or filesystem
- Schema loaded, parsed, and validated at startup
- Startup fails with a clear error if the schema is invalid or missing

### Client Injection
- `GraphOrmClient` bean auto-configured and injectable
- Typed client beans generated from schema (via code generator)

### GraphQL Integration
- `GraphQLSchema` bean registered with Spring for GraphQL
- DataFetchers auto-registered
- DataLoaderRegistry wired per request (request-scoped)

### CLI Commands
- `graphorm validate <schema-file>` — validate a schema and report diagnostics
- `graphorm generate <schema-file> --output <dir>` — generate Java client code
- Exit code 0 on success, non-zero on error
- Human-readable output for both commands

### Developer Documentation
- Quickstart guide: how to add GraphORM to a new Spring Boot project
- Configuration reference for all `graphorm.*` properties
- Code generation guide

## Expected Deliverables

1. A fresh Spring Boot project can add GraphORM with minimal configuration
2. Schema validation error at startup produces a useful, actionable message
3. Generated code is available during compilation
4. CLI commands work from the terminal
5. Developer documentation covers quickstart through configuration reference

---

## Acceptance Criteria

- [ ] The example application (`examples/nexus-commerce` or `graphorm-examples`) starts successfully with `mvn spring-boot:run`
- [ ] An intentionally invalid schema causes startup to fail with a human-readable error message (not a stack trace)
- [ ] `graphorm validate valid-schema.graphorm` exits with code 0 and prints "Schema is valid"
- [ ] `graphorm validate invalid-schema.graphorm` exits with code 1 and prints line:column diagnostics
- [ ] `graphorm generate schema.graphorm --output src/generated` produces `.java` files
- [ ] Generated client code compiles with the rest of the project
