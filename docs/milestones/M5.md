# M5 — Relationship Engine

**Status:** ⚪ Not Started
**Depends on:** M4

---

## Objective

Implement relational data fetching. After M5, queries can traverse relationships — loading related records correctly, efficiently, and without N+1 queries.

---

## Scope

### Relationship Types
- **One-to-one** — single record on each side; null if no match
- **Many-to-one** (belongs-to) — foreign key on the owning side; loads single referenced record
- **One-to-many** (has-many) — loads all child records for a given parent
- **Many-to-many** — via join table; loads all associated records

### Selection
- `include: { relation: true }` — eagerly load a relationship
- `include: { relation: { where: ..., orderBy: ..., skip: N, take: N } }` — nested filter and pagination
- `select: { relation: { select: { field: true } } }` — nested projection

### Batch Loading
- All `one-to-many` and `many-to-many` loads use `IN` queries: collect all parent IDs, issue one query
- Results grouped by parent ID
- `many-to-one` batched similarly: collect all foreign key values, issue one `IN` query

### Identity and Result Grouping
- Parent-to-child grouping is performed in memory after the batched query
- Null and missing relationships: `null` returned for required relations with no match; empty list for `one-to-many` with no children

### Circular Relationship Safeguards
- Depth limit on eager relationship loading (configurable, default: 5)
- Circular relationship detection: if model A includes model B which includes model A, the recursion terminates at the configured depth

### Nested Relationship Loading
- Multi-level relationships: `Order → OrderItems → Product`
- Depth is tracked and enforced
- Each level is independently batched

## Expected Deliverables

1. All four relationship types load correctly against real PostgreSQL
2. Batch loading eliminates per-parent queries for all relationship types

4. Nested relationship loading works to multiple levels
5. Null and missing relationships are handled correctly and explicitly

---

## Acceptance Criteria

- [ ] `findMany(Users, { include: { posts: true } })` with 100 users issues exactly 2 queries (verified by query counter)
- [ ] `findMany(Orders, { include: { items: { include: { product: true } } } })` issues at most 3 queries for any number of orders
- [ ] A many-to-many relationship loads correctly through the join table
- [ ] A one-to-one relationship returns `null` when no related record exists
- [ ] A one-to-many relationship returns an empty list when no children exist
- [ ] Circular relationship A→B→A terminates at the configured depth without stack overflow
