# M8 — Advanced PostgreSQL Features

**Status:** ⚪ Not Started
**Depends on:** M7

---

## Objective

Extend the query engine to support complex, production-grade PostgreSQL capabilities. These features address real enterprise workloads that simpler ORMs cannot handle without dropping to raw SQL.

---

## Scope

### Common Table Expressions (CTEs)
- `WITH` clause support in `QueryPlan`
- Recursive CTEs for hierarchical data (categories, organizational trees)
- CTE results referenced in main query

### Window Functions
- `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()`, `NTILE()`
- `LAG()`, `LEAD()` for time-series analysis
- `SUM() OVER (PARTITION BY ...)`, `AVG() OVER (...)`
- `FIRST_VALUE()`, `LAST_VALUE()`

### JSONB Support
- `@>` (contains), `<@` (contained by), `?` (key exists)
- `->` (get JSON object field), `->>` (get as text)
- `#>`, `#>>` path operators
- Filter by JSONB field value
- Index awareness for GIN-indexed JSONB columns

### Array Support
- PostgreSQL array types: `Int[]`, `String[]`, `UUID[]`
- Filter: `ANY(array_field) = value`, `array_field @> ARRAY[...]`
- Append, remove operations in updates

### Full-Text Search
- `to_tsvector` and `to_tsquery`
- `@@` match operator
- Rank by relevance (`ts_rank`)
- Multiple language configurations

### UPSERT
- `INSERT ... ON CONFLICT DO UPDATE`
- `ON CONFLICT DO NOTHING`
- Conflict target: specific columns or unique constraint

### LATERAL Joins
- For pagination within groups
- For correlated subqueries with limits

### Conditional Aggregation
- `SUM(CASE WHEN condition THEN value ELSE 0 END)`
- `COUNT(CASE WHEN condition THEN 1 END)`

### Advanced GROUP BY and HAVING
- Multi-field `GROUP BY`
- `HAVING` clause with aggregate conditions
- `ROLLUP` and `CUBE` grouping sets

### Native SQL API
- `nativeQuery(sql, params)` — executes parameterized raw SQL
- Returns typed results via `ResultSetMapper`
- Parameters must still be bound via prepared statement — no concatenation permitted

### Views and Materialized Views
- Read-only view models backed by database views
- Materialized view support (read-only, manual refresh)

## Acceptance Criteria

- [ ] A recursive CTE query over a category tree returns correctly nested results
- [ ] `ROW_NUMBER() OVER (PARTITION BY ...)` can be used in a window query and returns correct row numbers
- [ ] A JSONB filter `{ metadata: { path: ["key"], value: "foo" } }` matches records with that JSONB field value
- [ ] `createOrUpdate` using UPSERT inserts a new record and updates an existing one on conflict
- [ ] Full-text search over a `tsvector` column returns ranked results
- [ ] The native SQL API executes a raw `SELECT` and maps results correctly
- [ ] Unsupported features fail explicitly with a `GraphOrmException` rather than silently degrading
