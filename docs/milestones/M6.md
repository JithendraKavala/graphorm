# M6 — GraphQL Integration

**Status:** ⚪ Not Started
**Depends on:** M5

---

## Objective

Automatically connect GraphQL operations to GraphORM's query engine. After M6, a standard model query in a GraphQL schema requires no handwritten DataFetcher — GraphORM registers and handles it automatically.

---

## Scope

### GraphQL Schema Inspection
- Read and parse the GraphQL SDL schema
- Identify root query and mutation fields
- Match GraphQL type names to `EntityMetadata` registered in `ModelRegistry`

### DataFetcher Registration
- Register generic `DataFetcher` for each recognized root query field
- Accept `where`, `orderBy`, `skip`, `take`, `cursor` arguments
- Translate GraphQL arguments to `QueryPlan`
- Execute via the shared query engine
- Return results as `Map<String, Object>` for GraphQL Java

### Selection-Set Analysis
- Extract the requested fields from the `DataFetchingEnvironment`
- Handle aliases: resolve the actual field name from aliases
- Handle fragments and inline fragments
- Handle directives: `@skip` and `@include`
- Translate selected fields to projection columns in `QueryPlan`
- Detect relationship fields in the selection set and add dependency columns (e.g., foreign key columns needed for joining)

### Relationship DataFetcher Registration
- Register a `DataLoader`-backed `DataFetcher` for each relationship field
- Batch by parent IDs using `DataLoader`
- Use the relationship engine from M5 for actual loading

### DataLoader Integration
- Use `graphql-java`'s `DataLoaderRegistry`
- Each relationship has a named `DataLoader`
- Batch function collects all parent IDs, issues one batched query, groups results

### Mutation Support
- Register `DataFetcher` for `create`, `update`, `delete` mutations when identified in GraphQL schema
- Translate `input` arguments to `create`/`update` args
- Return the mutated record

### Custom Resolver Extension Points
- If a manual `DataFetcher` is registered for a field, do not override it
- Provide an extension point: `GraphOrmDataFetcherCustomizer` to override or augment generated behavior
- Support for `@graphorm:skip` or similar directive to opt out of automatic registration for a field

## Expected Deliverables

1. Standard model queries require no handwritten DataFetcher
2. Relationships are automatically resolved via DataLoader without N+1 queries
3. Selection sets influence database projections
4. Custom business logic can coexist with generated resolvers
5. All N+1 regression tests pass

---

## Acceptance Criteria

- [ ] A `users { id name posts { id title } }` query resolves correctly with exactly 2 database queries
- [ ] GraphQL aliases (`{ me: user(id: 1) { id } }`) resolve to the correct field
- [ ] GraphQL fragments and inline fragments are handled correctly in selection-set projection
- [ ] A manually registered `DataFetcher` for a field is not overridden by GraphORM
- [ ] `@skip(if: true)` removes the field from the database projection
- [ ] A `createUser(input: {...})` mutation creates the user and returns the created record
- [ ] N+1 query-count regression tests are in CI permanently
