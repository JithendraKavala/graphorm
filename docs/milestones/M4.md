# M4 — Query Engine and CRUD

**Status:** ⚪ Not Started
**Depends on:** M3

---

## Objective

Build the Prisma-inspired Java client. After M4, developers can perform all basic CRUD operations against PostgreSQL using a type-safe, composable query API without writing SQL.

---

## Scope

### Query Operations
- `findMany(FindManyArgs)` — returns a list of matching records
- `findUnique(FindUniqueArgs)` — returns exactly one record by unique key; throws if not found
- `findFirst(FindFirstArgs)` — returns the first matching record or empty
- `create(CreateArgs)` — inserts a single record, returns the created record
- `createMany(CreateManyArgs)` — batch insert, returns count
- `update(UpdateArgs)` — updates a single record by unique key
- `updateMany(UpdateManyArgs)` — updates all matching records, returns count
- `delete(DeleteArgs)` — deletes a single record by unique key
- `deleteMany(DeleteManyArgs)` — deletes all matching records, returns count
- `count(CountArgs)` — returns a count with optional filter

### Filter System
- `StringFilter` — `equals`, `contains`, `startsWith`, `endsWith`, `in`, `notIn`, `lt`, `lte`, `gt`, `gte`, `not`
- `IntFilter`, `FloatFilter`, `BigDecimalFilter` — `equals`, `lt`, `lte`, `gt`, `gte`, `in`, `notIn`, `not`
- `BooleanFilter` — `equals`, `not`
- `DateTimeFilter` — `equals`, `lt`, `lte`, `gt`, `gte`, `in`, `notIn`
- `NullableFilter<T>` — wraps any filter type with an `isNull` / `isNotNull` check
- Logical combinators: `AND`, `OR`, `NOT`

### Sorting
- `OrderBy` — field + direction (`ASC`, `DESC`)
- Null ordering: `NULLS FIRST`, `NULLS LAST`
- Multi-field sorting

### Pagination
- **Offset pagination:** `skip` + `take`
- **Cursor pagination:** `cursor` + `take` (after a unique field value)

### Projection/Selection
- `select` — explicit field selection; unspecified fields are not fetched

### Aggregates
- `aggregate(AggregateArgs)` — `count`, `sum`, `avg`, `min`, `max`
- `groupBy(GroupByArgs)` — group by field(s) with aggregate results

### QueryPlan
- Internal representation of a planned query
- `QueryPlan` — table, projected columns, filters, order, pagination, join specs
- SQL compilation from `QueryPlan` to parameterized SQL

## Expected Deliverables

2. Composable filter system that compiles to safe parameterized SQL

4. Aggregate queries
5. Integration test coverage for all operations

---

## Acceptance Criteria

- [ ] `findMany` with a complex filter (`AND`, `OR`, nested conditions) returns correct records
- [ ] `create` returns the full created record including generated fields
- [ ] `update` by unique key modifies only the specified record
- [ ] `deleteMany` with a filter removes only matching records
- [ ] No filter value is ever concatenated into SQL (verified by SQL log inspection in tests)
- [ ] Cursor pagination returns a stable result set when order is deterministic
- [ ] An `EntityNotFoundException` is thrown for `findUnique` when no record matches
