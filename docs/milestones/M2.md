# M2 — Schema Language and Parser

**Status:** ⚪ Not Started
**Depends on:** M1

---

## Objective

Allow developers to define their data models in a human-readable GraphORM schema file (`.graphorm`), inspired by Prisma's schema syntax. The parser must produce a complete AST and convert it into `EntityMetadata` for use by the rest of the framework.

---

## Scope

### Schema Grammar
- `datasource` block (provider, url)
- `generator` block (target language, output directory)
- `model` block with:
  - Scalar fields with optional `?` (nullable) and `[]` (list) modifiers
  - `@id` — primary key
  - `@unique` — unique constraint
  - `@default(value)` — default value (literal, `now()`, `uuid()`, `autoincrement()`)
  - `@map("column_name")` — database column name
  - `@updatedAt` — auto-update timestamp
  - `@@map("table_name")` — table name override
  - `@@unique([field1, field2])` — composite unique
  - `@@index([field1, field2])` — composite index
  - Relationship fields with `@relation` attribute
- `view` block — read-only database or virtual views
- `type` block — composite (embedded) types
- `enum` block — enumeration types
- Line comments (`//`) and block comments (`/* */`)

### Tokenizer and Parser
- Hand-written or ANTLR4 grammar
- Tracks source position (line and column) for all AST nodes
- Tolerant parsing: collects multiple errors rather than stopping at first

### AST Nodes
- `SchemaNode` — top-level container
- `ModelNode`, `ViewNode`, `CompositeTypeNode`, `EnumNode`
- `FieldNode` — name, type reference, modifiers, attributes
- `FieldAttributeNode`, `BlockAttributeNode`
- `ArgumentNode`, `LiteralNode` (string, int, float, boolean, array, function call)

### Semantic Validation
- Unknown type references rejected
- Undefined relation targets rejected
- Duplicate model/field names reported
- Missing `@id` reported
- Invalid `@default` for non-defaultable types reported
- Useful line:column error format

### Metadata Conversion
- `SchemaConverter` — converts validated AST into `EntityMetadata` objects
- Registers converted models with `ModelRegistry`

---

## Expected Deliverables

1. `.graphorm` files can be parsed into an AST
2. Invalid schemas produce actionable error messages with line:column context
3. Valid schemas produce complete `EntityMetadata` suitable for use by the query engine
4. The parser does not silently ignore unsupported syntax

---

## Acceptance Criteria

- [ ] The following schema parses correctly and produces valid metadata:

```graphorm
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String?
  createdAt DateTime @default(now())
  posts     Post[]

  @@map("users")
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  author   User   @relation(fields: [authorId], references: [id])
  authorId Int

  @@map("posts")
}
```

- [ ] The following produces a diagnostic at the correct line:

```graphorm
model Broken {
  id    Int  @id
  other Unknown   // "Unknown" is not defined
}
```

- [ ] Parser tests include at least: missing `@id`, unknown type reference, duplicate field name, malformed attribute syntax
- [ ] Parser does not silently skip unknown attributes — it either rejects them or warns about them
